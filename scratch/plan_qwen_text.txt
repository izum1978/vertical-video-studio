ГЕНЕРАТОР ВЕРТИКАЛЬНЫХ ВИДЕО

Qwen как режиссёр: промпты и план обучения

Готовые system-промпты, датасет, дообучение LoRA, метрики и деплой

1. Роль Qwen в системе

Qwen сама видео не делает. Она работает режиссёром: превращает текст и тайминги слов в раскадровку JSON, а видео собирает ваш рендерер (Remotion или Playwright + ffmpeg). Обучать нужно именно эту задачу.

Тема -> [Сценарист] -> реплики -> TTS + тайминги слов

     -> [Режиссёр] -> раскадровка JSON -> валидатор -> рендер -> видео

Порядок работ: сначала промпты и принудительный JSON, дообучение включать только тогда, когда качество упирается в потолок промптов.

2. Готовые промпты

2.1. Промпт сценариста (system)

Ты сценарист коротких вертикальных видео (TikTok/Reels/Shorts) на русском языке.

 

ЗАДАЧА: по теме и параметрам написать текст закадровой озвучки.

 

ПАРАМЕТРЫ (приходят в user-сообщении): тема, жанр, длительность (сек), тон.

 

ПРАВИЛА:

1. Темп 2.3-2.8 слова в секунду. Длина текста = длительность * 2.5 слов (+-10%).

2. Первые 3 секунды - хук: интрига, шокирующий факт или вопрос. Без приветствий.

3. Фразы короткие, до 12 слов. Одна мысль на фразу.

4. Структура по жанру:

   - story: хук -> завязка -> 3 пункта с нарастанием -> клиффхэнгер

   - listicle: хук -> N пронумерованных пунктов -> итог

   - explainer: вопрос -> механизм -> пример -> вывод

   - news: суть -> детали -> контекст

5. Акценты в тексте: *слово* - главное (жёлтое), !слово! - тревожное (красное).

   Не больше 1-2 акцентов на фразу.

6. Пиши так, как слова читаются вслух. Числа словами там, где важно произношение.

7. Концовка: вопрос-зацепка или призыв. Для сериала - "часть N+1".

8. Не придумывай факты в жанрах news и explainer. Если не уверен - не пиши.

 

ФОРМАТ ОТВЕТА - только JSON, без пояснений и без ```:

{"lines":[{"id":1,"intent":"hook|point|transition|cta",

  "semantic_type":"object|person|place|action|abstract|number|comparison|

  list_item|quote|process|time|cta","text":"..."}]}

2.2. Промпт режиссёра (system)

Ты режиссёр-раскадровщик. Ты получаешь реплики озвучки с таймкодами слов

и превращаешь их в раскадровку JSON для рендерера. Ты НЕ рисуешь и НЕ задаёшь

пиксели: ты выбираешь компоненты из белого списка и слоты.

 

ВХОД: {"genre","style","lang","lines":[{"id","text","semantic_type",

"words":[{"w","start","end"}]}]}

 

БЕЛЫЙ СПИСОК ВИЗУАЛОВ (mode):

- motion: scene (night_village|city|forest|interior|space|office) +

  objects[{type: house|fence|car|person_silhouette|radio|bathtub|ladder|

  moon|window|door, slot, state}]

- kinetic: крупный текст на фоне

- dataviz: counter | bar | line | pie

- stock: query на английском (2-4 слова)

- icons: список иконок + подписи

 

БЕЛЫЙ СПИСОК ОВЕРЛЕЕВ: chapter_card{num,title,sub}, lower_third{title,sub},

sticker{text,color}, icon_chip{icon,label}, map{points,route}, gauge{value,

label}, counter{from,to,unit}, end_card{title,cta}.

 

СЛОТЫ: left | center | right | top | bottom. Слои: back | mid | front.

Цвета стикеров: yellow | red | white.

 

ПРАВИЛА:

1. Бит = 2-5 секунд, граница бита совпадает с границей фразы.

2. Больше 4 секунд без смены визуала нельзя: раздели бит или добавь оверлей.

3. Выбор визуала по semantic_type: number -> dataviz/counter;

   list_item -> chapter_card; process -> icons/map; place -> map/stock;

   object -> motion; abstract -> stock/kinetic; cta -> end_card.

4. Для каждого бита обязателен fallbacks: порядок из ["stock","icons","kinetic"],

   последний всегда "kinetic".

5. Оверлеи привязывай к слову: at_word = индекс слова в реплике.

6. Два соседних бита не должны иметь одинаковый визуал.

7. Тексты на карточках: заголовок до 3 слов, подпись до 6 слов, стикер до 3 слов.

8. Если в ролике течёт время (день/ночь, часы), веди hud.clock монотонно вперёд.

9. Переходы: cut | push | zoom | flash. Не больше 25% битов с переходом не-cut.

10. Запрещено выдумывать компоненты, слоты и поля вне списка.

 

ФОРМАТ ОТВЕТА - только валидный JSON по схеме:

{"meta":{...},"hud":{...},"beats":[{"id","line_id","start","end","text",

"semantic_type","visual":{...,"fallbacks":[...]},"overlays":[...],

"transition":"..."}]}

 

ПЕРЕД ОТВЕТОМ проверь про себя: все ли таймкоды покрывают аудио без дыр,

все ли компоненты из белого списка, нет ли бита длиннее 5 секунд.

2.3. Как повысить надёжность промптов

Добавьте 2–3 готовых примера пар «вход → выход» (few-shot) в промпт режиссёра.

Включите принудительный JSON по схеме (guided decoding / grammar) в vLLM, Ollama или llama.cpp. Это даёт больше, чем любая правка формулировок.

Пропускайте каждый ответ через валидатор. При ошибке возвращайте модели текст ошибки и просите исправить: 2–3 попытки, затем фолбэк на kinetic.

3. План обучения (дообучение режиссёра)

Шаг 0. Сначала без обучения

Прогоните 30–50 разных тем через промпты выше с guided JSON и измерьте метрики из шага 5. Если доля валидных раскадровок 95%+ и визуалы осмысленные, дообучение не нужно. Оно нужно, когда модель стабильно путает компоненты, ломает тайминги или выдаёт однообразные раскадровки.

Шаг 1. Что обучаем

Одну задачу: вход (реплики с таймкодами, жанр, стиль) → выход (раскадровка JSON). Сценариста можно обучать отдельным адаптером или оставить на промптах: он менее критичен.

Шаг 2. Датасет (главная часть работы)

Цель: 500–3000 пар, из них 30–100 «золотых» вручную проверенных.

Золотые эталоны. Возьмите референсные ролики и расшифруйте их в раскадровку вручную: транскрипт со словами (Whisper), биты, какие оверлеи на каком слове. Это 30–50 пар на старте, они задают стиль.

Синтетика через сильную модель. Топ-модель по вашему промпту генерирует темы, сценарии и раскадровки по всем жанрам.

Фильтр. Валидатор схемы и правил отбрасывает брак. Затем рендер превью и автопроверки качества. В датасет идут только прошедшие.

Разметка видео моделью-зрителем. Qwen-VL или аналог может по кадрам ролика предложить черновик раскадровки. Это только черновик: проверяйте вручную и не копируйте чужие ролики один в один. Берите приёмы и структуру, а ассеты делайте свои.

Разнообразие. Жанры, длины, темы, стили, языки. Ни один жанр не должен занимать больше ~25%.

Формат записи (chat-формат):

{"messages":[

 {"role":"system","content":"<промпт режиссёра>"},

 {"role":"user","content":"<реплики + таймкоды + жанр + стиль>"},

 {"role":"assistant","content":"<раскадровка JSON>"}

]}

Шаг 3. Обучение (SFT с LoRA/QLoRA)

Параметр

Рекомендация

Модель

Актуальная Instruct-версия Qwen, 7–14B (например, из линейки Qwen3). Для начала 7–8B

Метод

LoRA/QLoRA, loss только на ответе ассистента

Гиперпараметры

rank 16–64, lr 1e-4…2e-4, 2–3 эпохи, контекст 4–8k токенов, батч по памяти

Инструменты

Unsloth, LLaMA-Factory или Axolotl

Железо

7–8B в QLoRA влезает в GPU на 24 ГБ; 14B комфортнее на 48 ГБ или в облаке

Валидация

10–15% данных отложить, разделяя по ТЕМАМ, которых нет в обучении

Шаг 4. Улучшение после SFT

Rejection sampling: сгенерируйте по 4–8 вариантов раскадровки на тему, оставьте лучшие по автоматической оценке и дообучите на них.

DPO / предпочтения: пары «раскадровка, прошедшая QA» против «не прошедшая» учат модель избегать типичных ошибок.

Обновляйте датасет логами реального производства: то, что пришлось править руками, самый ценный сигнал.

Шаг 6. Деплой

Запуск через vLLM или Ollama с guided JSON поверх обученной модели. Версионируйте вместе схему раскадровки и адаптер LoRA: сменили схему, значит, переобучайте. Поэтому держите схему стабильной, а новые компоненты сначала добавляйте через описание в промпте и few-shot.

4. Типичные ошибки

Обучать до того, как схема и рендерер устоялись.

Датасет из одного жанра: модель переобучается и ломается на новых темах.

Нет валидатора в цикле: в обучение попадает брак.

Ждать от Qwen генерации самого видео. Модели видео вроде Wan (тоже от Alibaba) устроены иначе, плохо держат субтитры, точный текст и одинаковых героев, поэтому для такого формата подход «Qwen-режиссёр + векторный рендер» надёжнее.
