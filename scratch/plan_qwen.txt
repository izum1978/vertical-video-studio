ГЕНЕРАТОР ВЕРТИКАЛЬНЫХ ВИДЕОQwen как режиссёр: промпты и план обученияГотовые system-промпты, датасет, дообучение LoRA, метрики и деплой1. Роль Qwen в системеQwen сама видео не делает. Она работает режиссёром: превращает текст и тайминги слов в раскадровку JSON, а видео собирает ваш рендерер (Remotion или Playwright + ffmpeg). Обучать нужно именно эту задачу.Тема -> [Сценарист] -> реплики -> TTS + тайминги слов     -> [Режиссёр] -> раскадровка JSON -> валидатор -> рендер -> видеоПорядок работ: сначала промпты и принудительный JSON, дообучение включать только тогда, когда качество упирается в потолок промптов.2. Готовые промпты2.1. Промпт сценариста (system)Ты сценарист коротких вертикальных видео (TikTok/Reels/Shorts) на русском языке. ЗАДАЧА: по теме и параметрам написать текст закадровой озвучки. ПАРАМЕТРЫ (приходят в user-сообщении): тема, жанр, длительность (сек), тон. ПРАВИЛА:1. Темп 2.3-2.8 слова в секунду. Длина текста = длительность * 2.5 слов (+-10%).2. Первые 3 секунды - хук: интрига, шокирующий факт или вопрос. Без приветствий.3. Фразы короткие, до 12 слов. Одна мысль на фразу.4. Структура по жанру:   - story: хук -> завязка -> 3 пункта с нарастанием -> клиффхэнгер   - listicle: хук -> N пронумерованных пунктов -> итог   - explainer: вопрос -> механизм -> пример -> вывод   - news: суть -> детали -> контекст5. Акценты в тексте: *слово* - главное (жёлтое), !слово! - тревожное (красное).   Не больше 1-2 акцентов на фразу.6. Пиши так, как слова читаются вслух. Числа словами там, где важно произношение.7. Концовка: вопрос-зацепка или призыв. Для сериала - "часть N+1".8. Не придумывай факты в жанрах news и explainer. Если не уверен - не пиши. ФОРМАТ ОТВЕТА - только JSON, без пояснений и без ```:{"lines":[{"id":1,"intent":"hook|point|transition|cta",  "semantic_type":"object|person|place|action|abstract|number|comparison|  list_item|quote|process|time|cta","text":"..."}]}2.2. Промпт режиссёра (system)Ты режиссёр-раскадровщик. Ты получаешь реплики озвучки с таймкодами слови превращаешь их в раскадровку JSON для рендерера. Ты НЕ рисуешь и НЕ задаёшьпиксели: ты выбираешь компоненты из белого списка и слоты. ВХОД: {"genre","style","lang","lines":[{"id","text","semantic_type","words":[{"w","start","end"}]}]} БЕЛЫЙ СПИСОК ВИЗУАЛОВ (mode):- motion: scene (night_village|city|forest|interior|space|office) +  objects[{type: house|fence|car|person_silhouette|radio|bathtub|ladder|  moon|window|door, slot, state}]- kinetic: крупный текст на фоне- dataviz: counter | bar | line | pie- stock: query на английском (2-4 слова)- icons: список иконок + подписи БЕЛЫЙ СПИСОК ОВЕРЛЕЕВ: chapter_card{num,title,sub}, lower_third{title,sub},sticker{text,color}, icon_chip{icon,label}, map{points,route}, gauge{value,label}, counter{from,to,unit}, end_card{title,cta}. СЛОТЫ: left | center | right | top | bottom. Слои: back | mid | front.Цвета стикеров: yellow | red | white. ПРАВИЛА:1. Бит = 2-5 секунд, граница бита совпадает с границей фразы.2. Больше 4 секунд без смены визуала нельзя: раздели бит или добавь оверлей.3. Выбор визуала по semantic_type: number -> dataviz/counter;   list_item -> chapter_card; process -> icons/map; place -> map/stock;   object -> motion; abstract -> stock/kinetic; cta -> end_card.4. Для каждого бита обязателен fallbacks: порядок из ["stock","icons","kinetic"],   последний всегда "kinetic".5. Оверлеи привязывай к слову: at_word = индекс слова в реплике.6. Два соседних бита не должны иметь одинаковый визуал.7. Тексты на карточках: заголовок до 3 слов, подпись до 6 слов, стикер до 3 слов.8. Если в ролике течёт время (день/ночь, часы), веди hud.clock монотонно вперёд.9. Переходы: cut | push | zoom | flash. Не больше 25% битов с переходом не-cut.10. Запрещено выдумывать компоненты, слоты и поля вне списка. ФОРМАТ ОТВЕТА - только валидный JSON по схеме:{"meta":{...},"hud":{...},"beats":[{"id","line_id","start","end","text","semantic_type","visual":{...,"fallbacks":[...]},"overlays":[...],"transition":"..."}]} ПЕРЕД ОТВЕТОМ проверь про себя: все ли таймкоды покрывают аудио без дыр,все ли компоненты из белого списка, нет ли бита длиннее 5 секунд.2.3. Как повысить надёжность промптовДобавьте 2–3 готовых примера пар «вход → выход» (few-shot) в промпт режиссёра.Включите принудительный JSON по схеме (guided decoding / grammar) в vLLM, Ollama или llama.cpp. Это даёт больше, чем любая правка формулировок.Пропускайте каждый ответ через валидатор. При ошибке возвращайте модели текст ошибки и просите исправить: 2–3 попытки, затем фолбэк на kinetic.3. План обучения (дообучение режиссёра)Шаг 0. Сначала без обученияПрогоните 30–50 разных тем через промпты выше с guided JSON и измерьте метрики из шага 5. Если доля валидных раскадровок 95%+ и визуалы осмысленные, дообучение не нужно. Оно нужно, когда модель стабильно путает компоненты, ломает тайминги или выдаёт однообразные раскадровки.Шаг 1. Что обучаемОдну задачу: вход (реплики с таймкодами, жанр, стиль) → выход (раскадровка JSON). Сценариста можно обучать отдельным адаптером или оставить на промптах: он менее критичен.Шаг 2. Датасет (главная часть работы)Цель: 500–3000 пар, из них 30–100 «золотых» вручную проверенных.Золотые эталоны. Возьмите референсные ролики и расшифруйте их в раскадровку вручную: транскрипт со словами (Whisper), биты, какие оверлеи на каком слове. Это 30–50 пар на старте, они задают стиль.Синтетика через сильную модель. Топ-модель по вашему промпту генерирует темы, сценарии и раскадровки по всем жанрам.Фильтр. Валидатор схемы и правил отбрасывает брак. Затем рендер превью и автопроверки качества. В датасет идут только прошедшие.Разметка видео моделью-зрителем. Qwen-VL или аналог может по кадрам ролика предложить черновик раскадровки. Это только черновик: проверяйте вручную и не копируйте чужие ролики один в один. Берите приёмы и структуру, а ассеты делайте свои.Разнообразие. Жанры, длины, темы, стили, языки. Ни один жанр не должен занимать больше ~25%.Формат записи (chat-формат):{"messages":[ {"role":"system","content":"<промпт режиссёра>"}, {"role":"user","content":"<реплики + таймкоды + жанр + стиль>"}, {"role":"assistant","content":"<раскадровка JSON>"}]}Шаг 3. Обучение (SFT с LoRA/QLoRA)ПараметрРекомендацияМодельАктуальная Instruct-версия Qwen, 7–14B (например, из линейки Qwen3). Для начала 7–8BМетодLoRA/QLoRA, loss только на ответе ассистентаГиперпараметрыrank 16–64, lr 1e-4…2e-4, 2–3 эпохи, контекст 4–8k токенов, батч по памятиИнструментыUnsloth, LLaMA-Factory или AxolotlЖелезо7–8B в QLoRA влезает в GPU на 24 ГБ; 14B комфортнее на 48 ГБ или в облакеВалидация10–15% данных отложить, разделяя по ТЕМАМ, которых нет в обученииШаг 4. Улучшение после SFTRejection sampling: сгенерируйте по 4–8 вариантов раскадровки на тему, оставьте лучшие по автоматической оценке и дообучите на них.DPO / предпочтения: пары «раскадровка, прошедшая QA» против «не прошедшая» учат модель избегать типичных ошибок.Обновляйте датасет логами реального производства: то, что пришлось править руками, самый ценный сигнал.Шаг 5. ОценкаМетрикаЦельВалидный JSON и схема с первой попытки98%+Все компоненты из белого списка100%Таймкоды без дыр и перекрытий99%+Доля битов, ушедших в фолбэкменее 15%Разнообразие (нет подряд одинаковых визуалов)95%+Слепая оценка людьми «выглядит как нужный стиль»выше базовой моделиВсегда сравнивайте с базовой Qwen на тех же 50 темах, иначе непонятно, дало ли обучение пользу.Шаг 6. ДеплойЗапуск через vLLM или Ollama с guided JSON поверх обученной модели. Версионируйте вместе схему раскадровки и адаптер LoRA: сменили схему, значит, переобучайте. Поэтому держите схему стабильной, а новые компоненты сначала добавляйте через описание в промпте и few-shot.4. Типичные ошибкиОбучать до того, как схема и рендерер устоялись.Датасет из одного жанра: модель переобучается и ломается на новых темах.Нет валидатора в цикле: в обучение попадает брак.Ждать от Qwen генерации самого видео. Модели видео вроде Wan (тоже от Alibaba) устроены иначе, плохо держат субтитры, точный текст и одинаковых героев, поэтому для такого формата подход «Qwen-режиссёр + векторный рендер» надёжнее.5. ГЕНЕРАТОР ВЕРТИКАЛЬНЫХ ВИДЕОУниверсальный план: от любого сценария до готового ролика 9:16Архитектура, этапы, схемы данных, дорожная карта и рискиФормат результата: вертикальное видео 1080×1920, 30 fps, 30–90 секунд, с озвучкой, субтитрами по словам и анимированной графикой.1. Принцип и общая схемаГлавная идея: содержание, режиссура и рендер разделены. Сценарий может быть любым, потому что между ним и картинкой стоит слой «смысловых типов» и несколько способов визуализации с запасными вариантами. LLM не рисует и не считает координаты: она выбирает из фиксированной библиотеки компонентов, а детерминированный рендерер собирает кадры.Вход (тема / готовый текст / ссылка на статью / файл)  -> [A] Нормализация и анализ жанра  -> [B] Сценарий (текст озвучки + акценты)  -> [C] Озвучка + тайминги каждого слова  -> [D] Разбиение на биты (смысловые куски по 2-5 сек)  -> [E] Режиссёр: выбор способа визуализации для каждого бита  -> [F] Сборка ассетов (SVG, сток, AI, графики)  -> [G] Раскадровка JSON -> валидация  -> [H] Таймлайн и рендер  -> [I] Звук, нормализация, экспорт  -> [J] Автопроверка качества -> перегенерация проблемных битовКаждый этап принимает и отдаёт JSON по схеме. Любой этап можно запустить отдельно и подменить заглушкой (Mock Mode).2. Что показал разбор референсного роликаЭто анимированная векторная графика, а не сток-футаж. Монтажных склеек нет: сцена непрерывна, объекты въезжают, меняются и уходят.Постоянный HUD сверху: время (23:40 → 23:48), затем «НОЧЬ 2», «НОЧЬ 3» и красная плашка «СВЯЗИ НЕТ».Субтитры по словам: 1–3 слова на экране, ключевое слово жёлтое или красное, ещё не произнесённые слова притушены.Повторяющиеся компоненты: карточка главы («01 ТИШИНА»), именная плашка, стикеры-подписи, иконки-чипы, карта с маршрутом, манометр, финальная карточка «часть 2».Структура: хук, пронумерованные пункты, смена дня и ночи, клиффхэнгер с призывом подписаться.Вывод: модуль «визуал» на сток-видео такое не сделает. Нужен движок сцен, которым управляет LLM, а сток остаётся одним из запасных режимов.3. Этап A. Вход и определение жанраПоддерживаются четыре режима входа: тема одной строкой, готовый сценарий, статья по ссылке, список тезисов. LLM определяет жанр и параметры ролика. Жанр задаёт пресет: структуру, темп (слов в секунду), набор компонентов и стиль.ЖанрОсобенностиТипичная структураИстория / сторителлингэмоции, персонажи, времяхук → завязка → пункты → клиффхэнгерСписок / топнумерация, карточкихук → N пунктов → итогОбъяснялкасхемы, аналогиивопрос → механизм → пример → выводНовости / фактыцифры, даты, именасуть → детали → контекстМотивация / цитатакрупный текст, атмосфератезис → усиление → призывОбзор / промопродукт, сравнениепроблема → решение → плюсы → CTAТуториалшаги, действиярезультат → шаги → ошибки → итогЭто главный рычаг универсальности: новый жанр означает новый пресет, а не переписанный код.4. Объекты имеют состояния (светит / не светит, открыто / закрыто).Кэш: запросы к стокам и AI-картинки хэшируются и повторно не скачиваются.Лицензии: для каждого ассета хранятся источник и тип лицензии.Рост библиотеки: запросы без подходящего SVG логируются, по статистике дорисовываются новые иллюстрации.9. Этап G. Раскадровка и валидацияРаскадровка — единый JSON, по которому работают рендер, интерфейс и тесты. Позиции задаются слотами, а не пикселями, иначе LLM будет ломать вёрстку.{  "meta": {"genre": "listicle", "lang": "ru", "fps": 30,           "size": [1080, 1920], "style": "dark_thriller"},  "hud": {"enabled": true,          "items": [{"type": "clock", "start": "23:40"}]},  "beats": [{    "id": "b01",    "text": "Включат *свет*.",    "semantic_type": "object",    "start": 0.0, "end": 2.4,    "visual": {"mode": "motion", "scene": "night_village",      "objects": [{"type": "house", "slot": "left", "state": "lit"}],      "fallbacks": ["stock", "kinetic"]},    "overlays": [{"type": "sticker", "text": "ПОДСКАЗКА",                  "slot": "right", "at_word": 2}],    "transition": "cut"  }]}Что проверяет валидаторJSON Schema: типы и обязательные поля.Только компоненты и слоты из белого списка.Таймкоды покрывают всё аудио без дыр.Длина текста на карточках в пределах лимита.Нет двух одинаковых визуалов подряд.Ошибки возвращаются в LLM с описанием проблемы: максимум 2–3 попытки, затем принудительный фолбэк на kinetic.10. Этап H. Таймлайн и рендерДетерминизм: анимации считаются от номера кадра, а не от часов. Рендер одинаков при каждом запуске.Привязка к словам: оверлеи появляются на at_word, а не на абсолютной секунде.Переходы: cut, push, zoom, flash. 3–4 вида, чередовать.Субтитры: чанки по 1–3 слова, подсветка акцентов, произнесённое слово ярче будущих, автоперенос и уменьшение шрифта при переполнении.Safe-зоны: верх около 12% и низ около 25% не занимать важным контентом (интерфейс платформ).Движок: Remotion, если стек Node/React; Playwright-кадры плюс ffmpeg, если Python (FastAPI). Сразу рендерить в 1080×1920, 30 fps, h264.Параллелизм: разбить рендер на диапазоны кадров и склеить, это ускоряет сборку в несколько раз.11. Этап I. ЗвукГолос плюс подложка с ducking (на 18–22 дБ тише под голосом).SFX по меткам битов: whoosh на переходах, «пинг» на цифрах, удар на хуке.Нормализация loudnorm до −14 LUFS, лимитер на −1 dBTP.Музыка только из лицензионной библиотеки, выбор по настроению жанра.12. Этап J. Автоконтроль качестваПроверки после рендера:длительность в заданном диапазоне;нет статичного куска дольше 3 секунд (разница между кадрами);нет чёрных кадров и тишины дольше 1 секунды;громкость в норме;текст не выходит за границы (по метаданным компонентов);контраст субтитров достаточный.Если бит не прошёл проверку, перегенерируется только он, а не весь ролик.13. Приёмы удержания вниманияВстраиваются в пресеты жанров.Смена визуала каждые 2–4 секунды.Первый кадр сразу с сутью, без заставок.Счётчик или прогресс на экране для интриги.Нумерация пунктов («01», «02») создаёт ощущение структуры.Финал с вопросом-зацепкой и призывом к действию.Возможность зацикливания: конец плавно ведёт к началу.14. Интерфейс и управлениеОчередь задач со статусами по этапам и логами в реальном времени.Экран «раскадровка»: список битов с миниатюрами, правка текста, смена визуала для одного бита, кнопка «перегенерировать бит».Редактор JSON для продвинутых пользователей.Библиотека готовых видео и повторный рендер с другим стилем без перегенерации сценария.Пакетный режим: загрузил 20 тем и получил 20 роликов.15. ТестированиеЗолотой набор: 10–15 сценариев по всем жанрам, прогоняемых после каждого изменения.Снапшот-тесты: ключевые кадры сравниваются с эталоном.Тесты фолбэков: намеренно ломать API стоков и проверять, что видео всё равно собирается.Метрики: доля битов, ушедших в фолбэк; среднее время рендера; число перегенераций.16.
