# ⚡ Vertical Video Studio

> **Профессиональная студия автоматической генерации вертикальных видео (YouTube Shorts, Instagram Reels, TikTok)**  
> **Формат на выходе:** H.264 MP4, 1080×1920 (9:16), 60 FPS Ultra HD (Lanczos-скейлинг, адаптивная резкость unsharp, сочные цвета, нормализация звука -14 LUFS, динамические вирусные субтитры по центру).

---

## 🚀 Быстрый старт в 1 клик (Windows)

Если вы работаете на Windows, в корне проекта готовы bat-скрипты:

1. **Запустить всё сразу:** дважды кликните `start_all.bat` (он запустит бэкенд и фронтенд в двух окнах).
2. Или по отдельности:
   - `run_backend.bat` — создаст `.venv`, установит зависимости и поднимет FastAPI на `http://127.0.0.1:8000`.
   - `run_frontend.bat` — установит npm-пакеты и откроет студию на `http://localhost:5173`.

> 💡 **Первый запуск без ключей:** оставьте включённым тумблер **Mock Mode**. Видео соберётся локально без вызовов платных API — вы сразу увидите готовый MP4 ролик и проверите работу FFmpeg.

## 🛠 Системные требования

- **Python:** 3.10+ (проверено на Python 3.10–3.14)
- **Node.js:** 18+ и npm
- **FFmpeg и FFprobe в системном PATH:**
  - **Windows:** `winget install Gyan.FFmpeg` *(или `choco install ffmpeg`)*
  - **macOS:** `brew install ffmpeg`
  - **Linux (Ubuntu/Debian):** `sudo apt update && sudo apt install ffmpeg`
  - **Linux (Fedora):** `sudo dnf install ffmpeg`

> *После установки FFmpeg на Windows обязательно перезапустите терминал, чтобы обновились переменные PATH.*

## 🎨 Стили субтитров (ASS)

Субтитры генерируются на лету в формате ASS (Advanced SubStation Alpha) с точной привязкой по времени:
- **Размер шрифта:** 96 pt (крупный, отлично читаемый с экрана смартфона)
- **Цвет текста:** Ярко-жёлтый `&H0000F0FF`
- **Обводка:** Глубокая чёрная обводка толщиной 8 px для максимальной контрастности на любом фоне
- **Позиционирование:** Строго по центру экрана (Alignment 5)
- **Группировка:** Динамические фразы по 3 слова (классический формат retention-субтитров TikTok/Shorts)

## ❓ Частые вопросы и Troubleshooting

### 1. `ffprobe` или `ffmpeg` не найден при старте
Убедитесь, что FFmpeg установлен и прописан в системную переменную `PATH`.
Для проверки выполните в терминале:
```bash
ffmpeg -version
```
Если команда не распознается, перезапустите терминал или IDE после установки через `winget install Gyan.FFmpeg`.

### 2. Кириллица в субтитрах отображается некорректно
По умолчанию используется шрифт `Arial`. Если вы меняете `SUBTITLE_FONT` в `.env`, убедитесь, что указанный шрифт установлен в системе и содержит символы кириллицы (например: `Montserrat`, `Roboto`, `Arial Black`).

### 3. Где хранятся готовые видео?
Все готовые видео сохраняются в папке `output/` в двух видах:
- `{id}.mp4` — готовый видеоролик высокой чёткости.
- `{id}.json` — метаданные (заголовок, хук, тема, длительность, теги, дата, источник раскадровки).
Файлы можно скачивать напрямую через веб-интерфейс или забирать из папки `output/` для автопостинга ботами.

## 🧠 Локальный Режиссёр (Director v2) и Дообучение Qwen

В проекте используется двухуровневая архитектура для локальной модели Qwen:
* **Сценарист:** настраивается через `OLLAMA_SCRIPT_MODEL` (или базовая `OLLAMA_MODEL=qwen2.5:7b`).
* **Режиссёр (Director v2):** настраивается через `OLLAMA_DIRECTOR_MODEL`, видит полный текст предложений с реальными таймкодами Edge-TTS, использует принудительную JSON-схему и повторяет генерацию с передачей ошибок валидатора.
* **Диспетчер сцен (`scene_resolver`):** гарантирует приоритет выбора режиссёра и исключает ложные срабатывания ключевых слов.

### Пайплайн дообучения и экспорта в Ollama (Ф6–Ф8):
1. **Сборка датасета из боевого пайплайна:**
   ```bash
   python training/build_director_dataset.py --topics training/topics.txt --script-provider claude --director-provider claude --tts edge
   ```
2. **Дообучение LoRA (QLoRA Unsloth) и автоэкспорт GGUF:**
   ```bash
   python training/train_director.py --epochs 3
   ```
   Скрипт проверяет токенизацию, обучает только на ответах ассистента, сохраняет лучший чекпоинт по `eval_loss`, конвертирует веса в GGUF и генерирует `Modelfile` с `num_ctx 8192`.
3. **Регистрация модели в Ollama:**
   ```bash
   cd training/out_director
   ollama create qwen2.5-director-v1 -f Modelfile
   ```
   Затем пропишите в `.env`:
   ```env
   OLLAMA_DIRECTOR_MODEL=qwen2.5-director-v1
   ```
4. **Оценка и слепое сравнение на отложенной выборке (Ф8):**
   ```bash
   python training/eval_director.py --models qwen2.5:7b qwen2.5-director-v1 --limit 50
   ```

## Визуал «Motion graphics» (стиль референсов)

Режим `motion_gfx` (в интерфейсе «🎞️ Motion graphics») рисует ролик тёмной векторной анимацией, как в присланных
референсах. Работает без GPU и без сети, рендер 30-секундного ролика занимает около минуты на обычном CPU.

**Что рисуется**
- постоянный HUD: время (идёт вперёд по ходу ролика), статус «СВЯЗИ НЕТ», метка «НОЧЬ 2» по словам из текста;
- карточка главы «01 ТИШИНА» с огромной бледной цифрой: появляется сама на фразах «Правило первое: …», «Шаг 2 …»;
- плашка персонажа («ЛЁВА, 52 / ЛЕСНИК») по фразе «Лёва, 52 года, лесник»; стикеры из `overlays` режиссёра;
- 24 сцены: ночной посёлок, радио, сосед у забора, звук с кругами, лестница, вода в ванне, манометр, трасса,
  карта маршрута, дом со светом в окне, иконки-подсказки (серия «ночная история») и универсальные: крупный текст,
  цифра-счётчик, чек-лист, хронология, сравнение, цитата, телефон, терминал, шаги, карточки, город, офис, финальная карточка;
- субтитры в стиле «ref»: фразы по 1–4 слова, произнесённые слова яркие, будущие приглушены, акценты жёлтые (`*слово*`)
  и красные (`!слово!`).

**Как выбирается сцена.** Режиссёр (Qwen) возвращает `scene_type` из списка `SCENE_CHOICES` (`backend/app/scene_resolver.py`);
если он пуст, сцену выбирают ключевые слова по границам слов и ротация. Старые имена сцен (`window_stalker` и др.) по-прежнему
принимаются и приводятся к новым (`backend/app/motion_gfx/engine.py`, таблица `LEGACY`). Причина выбора пишется в `meta.json`
(`scene_reasons`).

**Как добавить свою сцену.** 1) функция `my_scene(cv, t, dur, beat, st)` в `motion_gfx/scenes_*.py`; 2) строка в словаре `SCENES`
(`engine.py`); 3) имя в `SCENE_RENDERERS`, `SCENE_CHOICES` и подсказка в `SCENE_HINTS` (`scene_resolver.py`); 4) тест
`test_every_known_scene_name_maps_to_a_drawing` подскажет, если что-то забыто. После добавления сцен собирайте датасет v2 и
переобучайте режиссёра, иначе модель про них не знает.

**Настройки** (`.env`): `MOTION_WIDTH` (720 по умолчанию, 1080 чётче и медленнее), `MOTION_FPS`, `MOTION_FONT` (жирный шрифт с
кириллицей, по умолчанию ищутся Arial Black, Arial Bold, Segoe UI Bold, DejaVu Sans Bold).

Тесты: `pytest tests` (70 тестов, в том числе отрисовка каждой сцены и детали и короткий рендер через ffmpeg).

## Художник сцен: новая сцена под каждую фразу

Готовых сцен мало для «любой истории», поэтому движок умеет **рисовать сцену под каждый бит** из библиотеки деталей.

**Как это работает**
1. Режиссёр (Qwen) для бита, где нужной готовой сцены нет, ставит `scene_type: "custom"` и коротко пишет в `visual`, что показать.
2. Художник (`backend/app/motion_gfx/designer.py`) превращает фразу в описание сцены (JSON): фон (ночь, закат, день, комната, космос, подводный, шторм), земля, погода, до 16 деталей из библиотеки (62 штуки: дом, дерево, машина, человек, сковорода, ракета, ноутбук и др.), анимации (качание, мерцание, дрейф, пульс, вращение, орбита) и движение камеры.
3. Описание проверяется и приводится к безопасному виду (`scene_dsl.normalize_spec`): неизвестные детали отбрасываются, координаты и размеры ограничиваются, поле субтитров остаётся свободным. Если композиция слабая (мало деталей, все в одной точке), LLM получает замечания и пробует ещё раз.
4. Если LLM недоступна или не справилась, сцену собирает **офлайн-художник по словарю** (`lexicon.py`): находит в тексте предметы, выбирает фон и расставляет их (мелкие предметы кладёт на стол). Если предметов нет, бит показывается крупным текстом, а не случайной сценой.
5. Готовые описания кэшируются в `work/scene_cache` и сохраняются в `meta.json`, поэтому повторный рендер даёт ту же сцену.

**Режимы** (`scene_gen` в запросе и в интерфейсе): `auto` (только биты без подходящей готовой сцены, LLM затем словарь), `all` (рисуем заново все биты), `heuristic` (только словарь, без LLM, быстро), `off` (только готовые сцены).

**Модель для сцен.** Для локальной Qwen используется `OLLAMA_SCENE_MODEL` (или базовая `OLLAMA_MODEL`), а не дообученный режиссёр: тот учился на раскадровке и сцены рисовать не умеет. Сложные композиции заметно лучше получаются у сильных моделей (Claude, Gemini, GPT) или у Qwen 14B и больше; число параллельных запросов задаёт `SCENE_DESIGNER_WORKERS` (2 по умолчанию).

**Как расширить.** Новая деталь это функция с декоратором `@prop(...)` в `motion_gfx/props_world.py` или `props_things.py`, больше ничего регистрировать не нужно: деталь сразу попадает в схему и промпт художника. Чтобы офлайн-художник её находил, добавьте слова в `lexicon.py`. Тест `test_every_prop_renders_and_dynamic_props_change_over_time` проверит отрисовку.

**Ограничения.** Новые *предметы* появляются только из библиотеки; художник может добавить простые свободные фигуры (`shapes`: прямоугольник, эллипс, многоугольник, линия, текст), но сложные рисунки из них не соберёт. Детали плоские; у человека четыре позы (стоит, идёт, бежит, сидит, машет), у остальных одна.

### Как улучшить художника сцен на своей модели

Критик композиции (`designer.quality_errors`) отсекает слабые сцены: мало деталей, все в одной точке, детали налезают друг на друга или уходят за кадр, слишком мелкие, слишком много одинаковых. Замечания возвращаются в LLM для второй попытки. Офлайн-художник сам расталкивает налезающие детали.

Чтобы локальная Qwen рисовала сцены уверенно, её можно дообучить на сценах сильной модели:

```bash
# 1. сильная модель рисует сцены по фразам (training/scene_sentences.txt: 88 стартовых фраз, нужно 300+)
python training/build_scene_dataset.py --provider claude
# 2. обучение тем же скриптом, что и для режиссёра
python training/train_director.py --train training/data/scene_train.jsonl --val training/data/scene_val.jsonl \
    --out training/out_scene --tag qwen2.5-scene-v1
cd training/out_scene && ollama create qwen2.5-scene-v1 -f Modelfile
# 3. в .env:  OLLAMA_SCENE_MODEL=qwen2.5-scene-v1
# 4. сравнение моделей на отложенной выборке
python training/eval_scene.py --models qwen2.5:7b qwen2.5-scene-v1 --limit 40
```

В датасет попадают только сцены, прошедшие нормализацию, критик и проверку смысла (предметы из фразы есть в сцене). Сцены, которые нарисовал словарь, а не LLM, в датасет не берутся. Метрики `eval_scene.py`: `json` (валидный ответ), `сцена` (прошла нормализацию), `критик` (композиция без замечаний), `чужие_детали` (доля деталей не из библиотеки), `смысл` (доля предметов фразы в сцене), число и разнообразие деталей.
